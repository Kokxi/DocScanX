## 1. 整体架构

### 1.1 技术栈

| 层级 | 技术 | 版本要求 | 阶段 |
|------|------|----------|------|
| 语言 | Python | 3.8+ | 一期 |
| Web 框架 | FastAPI / Flask | FastAPI 0.100+ | 一期 |
| 前端 | HTML + CSS + JavaScript（无框架） | — | 一期 |
| OCR 引擎 | PaddleOCR / RapidOCR | PaddleOCR 2.6+ | 一期 |
| NER 模型 | PaddleNLP UIE | PaddleNLP 2.5+ | 一期 |
| 深度学习框架 | PaddlePaddle | CPU 版 2.4+ | 一期 |
| 文档解析 | python-docx / openpyxl / python-pptx / pdfplumber / PyMuPDF | — | 一期 |
| 打包工具 | PyInstaller（Windows） / pyinstaller + 路径适配（Linux） | 5.0+ | 一期 |
| LLM 客户端（二期） | openai 库 / httpx | — | 二期 |
| 远程文件-FTP（二期） | ftplib（内置） | — | 二期 |
| 远程文件-SFTP（二期） | paramiko | — | 二期 |
| 远程文件-CIFS/SMB（二期） | pysmb / smbprotocol | — | 二期 |
| 凭据加密（二期） | cryptography | — | 二期 |

## 2. 模型选型与下载指南

### 2.1 模型清单

| 模型 | 类型 | 必需 | 大小 | 来源 |
|------|------|------|------|------|
| UIE-Small | 信息抽取 | ✅ 必需 | ~100MB | PaddleNLP 模型库 |
| UIE-Tiny | 信息抽取 | ❌ 可选 | ~30MB | PaddleNLP 模型库 |
| UIE-Base | 信息抽取 | ❌ 可选 | ~400MB | PaddleNLP 模型库 |
| PaddleOCR V4 Lite | OCR | ✅ 必需 | ~12MB | PaddleOCR 模型库 |
| PaddleOCR NCNN Lite | OCR | ❌ 可选 | ~15MB | PaddleOCR NCNN 版 |

### 2.2 UIE 模型手动下载步骤

```bash
# 在有网环境中通过 PaddleNLP API 导出
pip install paddlenlp

python -c "
from paddlenlp.transformers import AutoModelForTokenClassification, AutoTokenizer

# 下载并导出 UIE-Small（必需）
model = AutoModelForTokenClassification.from_pretrained('uie-small-zh')
tokenizer = AutoTokenizer.from_pretrained('uie-small-zh')
model.save_pretrained('./models/uie-small')
tokenizer.save_pretrained('./models/uie-small')

# 可选：UIE-Tiny
model = AutoModelForTokenClassification.from_pretrained('uie-tiny-zh')
tokenizer = AutoTokenizer.from_pretrained('uie-tiny-zh')
model.save_pretrained('./models/uie-tiny')
tokenizer.save_pretrained('./models/uie-tiny')
"
```

### 2.3 OCR 模型手动下载步骤

```bash
# PaddleOCR V4 Lite 下载（必需）
wget https://paddleocr.bj.bcebos.com/PP-OCRv4/ch/ch_PP-OCRv4_det_infer.tar
wget https://paddleocr.bj.bcebos.com/PP-OCRv4/ch/ch_PP-OCRv4_rec_infer.tar
wget https://paddleocr.bj.bcebos.com/dygraph_v2.0/ch/ch_ppocr_mobile_v2.0_cls_infer.tar

# 解压到 models/ocr_paddle_v4_light/ 目录
mkdir -p ./models/ocr_paddle_v4_light/{det,rec,cls}
tar -xf ch_PP-OCRv4_det_infer.tar -C ./models/ocr_paddle_v4_light/det/
tar -xf ch_PP-OCRv4_rec_infer.tar -C ./models/ocr_paddle_v4_light/rec/
tar -xf ch_ppocr_mobile_v2.0_cls_infer.tar -C ./models/ocr_paddle_v4_light/cls/
```

## 3. 配置系统

### 3.1 配置文件结构 (config.yaml)

```yaml
# ─── 文件扫描 ───
scan:
  default_path: ""                        # 默认扫描路径
  include_subdir: true                    # 包含子目录
  extract_archive: true                   # 解压压缩包
  file_extensions:                        # 默认启用的后缀
    archive: [.zip, .rar, .7z]
    office_new: [.docx, .xlsx, .pptx]
    office_old: [.doc, .xls, .ppt]
    pdf: [.pdf]
    image: [.jpg, .jpeg, .png, .bmp, .tiff]
    text: [.txt, .csv, .md, .log]
    structured: [.json, .xml]
    dev: [.py, .java, .js, .html, .sql]
  extension_groups_default:               # 各分组默认勾选
    archive: true
    office_new: true
    office_old: false
    pdf: true
    image: true
    text: true
    structured: false
    dev: false

# ─── 模型 ───
model:
  uie:                                   # UIE 模型配置
    version: small                       # tiny / small / base
    path: ./models/uie-small
    schema: [name, id_card, phone, bank_card, address, email, wechat, birthday, job_no, plate_no, passport, gender]
  ocr:                                   # OCR 引擎配置
    engine: rapidocr                      # rapidocr（默认） / paddleocr_v4_light
    rapidocr_path: ./models/ocr_rapidocr
    paddleocr_path: ./models/ocr_paddle_v4_light

# ─── 推理 ───
inference:
  confidence_threshold: 0.65             # 实体置信度阈值
  text_chunk_size: 512                   # 文本分片大小（字符）
  text_chunk_overlap: 64                 # 分片重叠大小

# ─── PDF 判定 ───
pdf:
  text_threshold: 20                     # 文本层字符数阈值，超过判为文本PDF

# ─── 任务 ───
task:
  file_timeout: 300                      # 单文件处理超时（秒）
  max_retry: 3                           # 失败重试次数
  log_detail: true                       # 是否记录详细日志

# ─── 内存 ───
memory:
  max_memory_mb: 2048                    # 最大内存（MB）
  gc_watermark: 0.8                      # GC 触发水位（百分比）
  temp_clean_after_task: true            # 任务完成后清理临时文件

# ─── 并发 ───
concurrency:
  file_parse_workers: 2                  # 文件解析线程数
  ocr_workers: 1                         # OCR 推理线程数
  uie_workers: 1                         # UIE 推理线程数

# ─── 二期扩展：大模型（二期） ───
# llm:
#   enable: false                          # 启用/禁用（二期功能）
#   api_base: ""                           # API 地址，如 http://10.0.0.100:8000/v1
#   api_key: ""                            # API 密钥（加密存储）
#   model: ""                              # 模型名称，如 qwen2-72b
#   timeout: 30                            # 单次请求超时（秒）
#   max_retries: 3                         # 最大重试次数
#   confidence_boost: 0.8                  # 交叉验证时 LLM 结果权重
#   cross_validation: false                # 与 UIE 进行交叉验证
#
# ─── 二期扩展：远程文件源（二期） ───
# remote_sources:
#   - name: "HR-Server"                    # 源名称
#     protocol: ftp                        # ftp / sftp / cifs / smb
#     host: 10.0.0.50
#     port: 21
#     username: "scanuser"
#     password: ""                         # 加密存储，运行时解密
#     base_path: "/documents"
#     max_file_size_mb: 500
#     connect_timeout: 30
log:
  level: INFO                            # DEBUG / INFO / WARNING / ERROR
  max_days: 7                            # 日志保留天数
  max_size_mb: 10                        # 单日志文件上限
  path: ./logs

# ─── 路径 ───
path:
  output_dir: ./output                   # 报告输出目录
  temp_dir: ./temp                       # 临时文件目录
  model_dir: ./models                    # 模型目录
  log_dir: ./logs                        # 日志目录
```

### 3.2 配置热加载

- 配置文件仅在启动时加载
- 运行时配置变更通过 API 接口修改（修改内存中的配置副本）
- 用户可在前端"系统设置"页面实时调整参数
- 重启后恢复文件配置，支持"保存为默认"持久化

## 4. 内存管理与并发控制

### 4.1 内存水位管理

```
内存使用率
  ↑
  │
  │  警戒线 (80%) ───── 暂停启动新任务，等待当前任务完成
  │
  │  正常线 (60%) ───── 正常调度
  │
  │  空闲线 (30%) ───── 可加载更多模型
  └──────────────────────────────→ 时间
```

### 4.2 线程池模型

```
┌─────────────────────────┐
│      主调度线程         │
│  (任务分配 + 状态管理)   │
└────────┬────────────────┘
         │
    ┌────┴────┬────┬────┐
    │         │    │    │
    ▼         ▼    ▼    ▼
┌────────┐ ┌────┐ ┌──┐ ┌──┐
│ 文件解析 │ │OCR │ │UIE│ │..│
│ 线程池   │ │线程│ │线程│ │  │
│ (2)     │ │(1) │ │(1)│ │  │
└────────┘ └────┘ └──┘ └──┘
```

- 各线程池大小通过 `concurrency` 配置项控制
- OCR 和 UIE 模型在各自线程中独立加载（避免模型切换开销）
- 线程间通过内存队列传递数据（管道模式）

### 4.3 临时文件管理

| 场景 | 行为 |
|------|------|
| 解压压缩包 | 解压到 `temp/unpacked/{task_id}/` |
| 图片缓存 | 提取到 `temp/images/{task_id}/` |
| 任务完成 | 立即清理 `temp/{task_id}/` 整个目录 |
| 任务中断 | 保留 24 小时后清理 |
| 系统关闭 | 清理所有临时目录 |

## 5. 异常处理

### 5.1 错误分级

| 级别 | 行为 | 示例 |
|------|------|------|
| ERROR | 中断当前文件处理，记录到异常清单 | 文件损坏、加密 |
| WARN | 继续处理，记录警告 | 编码检测失败（使用降级编码） |
| INFO | 常规操作记录 | 开始处理、完成处理 |

### 5.2 错误传播

```
文件层     模块层      任务层
                                   
文件A出错 ─→ 文件解析模块 ─→ 记录到异常清单
    │            │              │
    │            │              ▼
    └── 跳过文件A ──→ 继续文件B → 任务状态：部分成功
```

### 5.3 超时机制

- 单文件解析超时：`task.file_timeout`（默认 300s）
- 单页 OCR 超时：硬编码 60s
- 单次 UIE 推理超时：硬编码 30s

## 6. 部署方式

### 6.1 源码部署

#### 环境准备

```bash
# 1. 安装 Python 3.8+
python --version   # 需 ≥ 3.8

# 2. 安装依赖（需在有网环境提前下载）
pip install -r requirements.txt -d ./packages/

# 3. 拷贝到内网后安装
pip install --no-index --find-links=./packages/ -r requirements.txt
```

#### 依赖清单 (requirements.txt)

```
paddlepaddle==2.4.2
paddlenlp==2.5.0
paddleocr>=2.6.0

jinja2>=3.1.0
```

#### 启动

```bash
# 4. 下载模型到 ./models/ 目录（参考第 2 节）

# 5. 启动
python main.py
# 默认访问 http://localhost:8080
```

### 6.2 单文件绿色部署

#### Windows EXE

```bash
# 使用 PyInstaller
pip install pyinstaller
pyinstaller --onefile --windowed --add-data "models;models" --add-data "templates;templates" main.py
```

#### Linux 可执行文件

```bash
# 使用 PyInstaller（Linux 环境下打包）
pip install pyinstaller
pyinstaller --onefile --add-data "models:models" --add-data "templates:templates" main.py
# 注意：Linux 路径分隔符使用冒号 :，Windows 使用分号 ;
```

#### 使用 Nuitka（可选，Linux/Windows 通用，体积更小）

```bash
# Nuitka 可将 Python 编译为原生可执行文件
pip install nuitka
nuitka --standalone --onefile --enable-plugin=tk-inter main.py
```

- 优点：用户无需安装 Python 和环境
- 缺点：PyInstaller 打包后体积较大（含 Python 解释器），启动略慢
- 建议：作为源码部署的补充方案，各平台分别打包

### 6.3 离线安装脚本

`setup_offline.bat`：

```batch
@echo off
REM DocScanX 离线安装脚本
echo ========================================
echo  DocScanX 离线安装工具
echo ========================================

REM 1. 检查 Python
python --version >nul 2>&1
if %errorlevel% neq 0 (
    echo [ERROR] 未检测到 Python，请先安装 Python 3.8+
    pause
    exit /b 1
)

REM 2. 安装依赖
echo [INFO] 正在安装依赖包...
pip install --no-index --find-links=./packages/ -r requirements.txt
if %errorlevel% neq 0 (
    echo [ERROR] 依赖安装失败
    pause
    exit /b 1
)

REM 3. 检查模型
if not exist "./models/uie-small" (
    echo [WARN] UIE-Small 模型未找到，请按《模型下载指南》手动下载
)

if not exist "./models/ocr_paddle_v4_light" (
    echo [WARN] OCR 模型未找到，请按《模型下载指南》手动下载
)

REM 4. 创建目录
if not exist "./output" mkdir output
if not exist "./logs" mkdir logs
if not exist "./temp" mkdir temp

echo ========================================
echo  安装完成！
echo  运行 python main.py 启动系统
echo  默认访问 http://localhost:8080
echo ========================================
pause
```

`setup_offline.sh`（Linux 环境）：

```bash
#!/bin/bash
# DocScanX 离线安装脚本（Linux）
set -e

echo "========================================"
echo " DocScanX 离线安装工具"
echo "========================================"

# 1. 检查 Python
if ! command -v python3 &>/dev/null && ! command -v python &>/dev/null; then
    echo "[ERROR] 未检测到 Python，请先安装 Python 3.8+"
    exit 1
fi
PYTHON=$(command -v python3 || command -v python)

# 2. 安装依赖
echo "[INFO] 正在安装依赖包..."
$PYTHON -m pip install --no-index --find-links=./packages/ -r requirements.txt

# 3. 检查模型
[ -d "./models/uie-small" ] || echo "[WARN] UIE-Small 模型未找到，请按《模型下载指南》手动下载"
[ -d "./models/ocr_paddle_v4_light" ] || echo "[WARN] OCR 模型未找到，请按《模型下载指南》手动下载"

# 4. 创建目录
mkdir -p output logs temp

echo "========================================"
echo " 安装完成！"
echo " 运行 $PYTHON main.py 启动系统"
echo " 默认访问 http://localhost:8080"
echo "========================================"
```

## 9. 技术边界与风险

### 9.1 已知边界

| 场景 | 一期限定 | 二期解决 |
|------|----------|----------|
| 手写文稿 | UIE 模型无法准确识别手写文字 | 二期通过大模型可支持（依赖模型能力） |
| 低质量扫描件 | 分辨率低于 150 DPI 的扫描件 OCR 准确率显著下降 | 二期大模型对低质量图像理解力更强 |
| 非中文文档 | 模型基于中文训练，暂不支持外文个人信息抽取 | 二期大模型支持多语言 |
| 图片中的表格 | 复杂表格结构（合并行/列）识别准确率有限 | 二期大模型端到端还原表格 |
| 超大文件（100MB+） | 单文件处理时间可能超时 | 同左（仍受限于文件大小） |
| 嵌套压缩包 | 超过 3 层嵌套的压缩包可能无法解压 | 同上 |
| 远程文件存储 | 仅支持本地文件系统扫描 | 二期支持 FTP/SFTP/CIFS/SMB |

### 9.2 风险缓解

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| PaddlePaddle 版本兼容 | Python 环境和依赖冲突 | 使用虚拟环境，明确版本锁定 |
| 内网模型下载困难 | 模型部署依赖有网导出 | 提供详细的模型下载指南，支持预打包模型包 |
| CPU 推理性能瓶颈 | 千级文件扫描耗时较长 | 异步并行，多线程优化 |
| 脱敏后仍可识别 | 脱敏不足导致隐私泄露 | 多重脱敏策略，支持用户自定义脱敏强度 |
| 误识别（假阳性） | 将非敏感信息误判为敏感 | 置信度阈值可调，支持人工审核 |
| 大量文件内存溢出 | 系统崩溃 | 内存水位监控，超过阈值暂停新任务 |
| **LLM API 不可用（二期）** | 大模型识别流程阻塞 | 自动降级至一期 OCR+UIE，不阻塞整个任务 |
| **远程连接不稳定（二期）** | 文件扫描中断或超时 | 重试机制 + 断点续传，连接前先测试可用性 |
| **凭据泄露风险（二期）** | 远程服务器凭据被窃取 | 加密存储凭据，运行时仅解密到内存

## 10. OCR 引擎对比

| 指标 | RapidOCR | PaddleOCR V4 Lite | PaddleOCR NCNN Lite |
|------|----------|------------------|-------------------|
| 模型大小 | ~8MB | ~12MB | ~15MB |
| 识别速度 | 较快 | 基准 | 更快（NCNN 优化） |
| 中文准确率 | 中 | 高 | 高 |
| 安装复杂度 | 低（pip 安装） | 低（pip 安装） | 中（需编译 NCNN） |
| 推荐场景 | **默认首选** + 自动降级 | 高精度模式 / RapidOCR 降级目标 | 对速度有极致需求 |

### 11.3 二期配置项（config.yaml 扩展段）

二期配置项**默认注释关闭**，一期加载器自动忽略，二期启用时逐项解注释：

```yaml
# ─── 二期大模型配置 ───
llm:
  enable: false                     # 启用/禁用
  api_base: ""                      # API 地址
  api_key: ""                       # 密钥（加密存储）
  model: ""                         # 模型名称
  timeout: 30                       # 超时（秒）
  max_retries: 3                    # 最大重试次数
  cross_validation: false           # 与 UIE 交叉验证
  confidence_boost: 0.8             # LLM 结果权重

# ─── 二期远程文件源配置 ───
remote_sources:
  - name: "HR-Server"
    protocol: ftp                   # ftp/sftp/cifs/smb
    host: "10.0.0.50"
    port: 21
    username: "scanuser"
    password: ""                    # 加密存储
    base_path: "/documents"
    max_file_size_mb: 500
    connect_timeout: 30
```

### 11.4 二期与一期共存原则

| 原则 | 说明 |
|------|------|
| **向后兼容** | 二期不修改一期模块的内部逻辑，仅扩展新模块 |
| **可选激活** | 二期模块默认关闭，通过配置项逐项启用 |
| **自动降级** | LLM 不可用时自动回退至 OCR+UIE 一期方案 |
| **共用管线** | 远程文件下载后与本地文件共用同一套解析/IPE/报告管线 |
| **代码隔离** | 二期代码放在 `modules/llm/` 和 `modules/remote/` 目录，不与一期混合 |
| **依赖隔离** | 二期依赖放在 `requirements-optional.txt`，不强制安装 |
