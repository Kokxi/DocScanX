## 2. 核心业务层 — 处理管线

### 2.1 任务调度引擎

**职责**：任务生命周期管理，协调各模块串联执行。

**状态机**：

```
等待中 ──→ 运行中 ──→ 已完成
                ├──→ 已暂停 ──→ 运行中（恢复）
                └──→ 已中断
```

**核心功能**：
- 任务队列管理（分阶段推进：文件发现 → 解析 → OCR → 抽取 → 关联 → 产出）
- 断点续传：记录每个文件的处理状态，中断后可跳过已完成的文件
- 并发控制：管理文件解析、OCR、UIE 三个线程池的大小
- 进度计算：根据总文件数和当前已处理数量计算百分比

**接口**：

| 方法 | 说明 |
|------|------|
| `create_task(path, config)` | 创建新扫描任务 |
| `start_task(task_id)` | 开始执行 |
| `pause_task(task_id)` | 暂停 |
| `resume_task(task_id)` | 恢复 |
| `stop_task(task_id)` | 停止 |
| `get_status(task_id)` | 查询状态 |

---

### 2.2 文件接入与解析模块

**职责**：扫描目录、发现文件、解压压缩包、按格式解析文本内容。

**处理流程（一期 - 本地文件）**：

```
扫描本地目录 → 文件后缀过滤 → 压缩包解压 → 格式分派 → 文本提取 → 输出纯文本
```

**处理流程（二期 - 远程文件）**：

```
连接远程服务器 → 目录浏览 → 文件列表获取 → 流式下载 → 临时缓存 → 格式分派 → ...
```

**格式解析器**：

| 文件类型 | 解析器 | 使用库 |
|----------|--------|--------|
| `.docx` | Word文档解析 | `python-docx` |
| `.xlsx` | Excel表格解析 | `openpyxl` |
| `.pptx` | PPT文档解析 | `python-pptx` |
| `.pdf` | PDF文本提取 | `pdfplumber` / `PyMuPDF` |
| `.txt/.csv/.md/.log` | 纯文本读取 | 内置文件IO |
| `.json` | JSON结构化读取 | `json` |
| `.xml` | XML解析 | `xml.etree` |
| `.doc/.xls/.ppt` | 老旧Office格式 | `win32com` 或 `olefile`（可选组件） |
| `.zip/.rar/.7z` | 压缩包解压 | `zipfile` + `pyunpack`或 `patool` |

**编码自动检测**：
- 优先检测 BOM（UTF-8/UTF-16）
- 其次使用 `chardet` 自动检测
- 降级至系统默认编码（Windows: gbk, Linux: utf-8）

**异常处理契约**：

| 异常场景 | 行为 |
|----------|------|
| 文件损坏/加密 | 跳过，记录到异常清单，不影响整体任务 |
| 不支持的格式 | 跳过，记录"格式不支持" |
| 单文件超时 | 跳过，记录"处理超时" |
| 解压失败 | 跳过该压缩包，记录"解压失败" |
| OCR失败 | 记录该页失败，继续下一页 |

### 2.3 PDF 智能判定模块

**职责**：区分文本型 PDF 和扫描件 PDF，决定走文本提取路线还是 OCR 路线。

**判定策略**：

```
PDF文件
  ├── 有文本层（可复制的文字） → 文本提取（直接读取）
  └── 无文本层或文字极少
        ├── 有嵌入式图片 → OCR识别
        └── 无图片 → 判定为无法处理，记录异常
```

**判断依据**：
1. 检查每页的文本字符数
2. 如果字符数 > 设定阈值（默认 20），判为文本 PDF
3. 否则检查页面中是否包含图片
4. 有图片 → 走 OCR；无图片 → 走异常

---

### 2.4 OCR 识别引擎

**职责**：对图片/扫描件 PDF 执行文字识别，输出带坐标的文本块。

**支持的引擎**：

| 引擎 | 默认 | 磁盘 | 速度 | 准确率 |
|------|------|------|------|--------|
| RapidOCR | ✅ 默认首选 | ~8MB | 较快 | 中 |
| PaddleOCR V4 Lite | ❌ 可选 | ~12MB | 快 | 高 |
| PaddleOCR NCNN Lite | ❌ 可选 | ~15MB | 更快（NCNN优化） | 高 |

**引擎选择与切换策略**：

用户在前端系统设置中二选一，互斥，实时生效（下次扫描任务）：

1. **RapidOCR（默认）**：优先使用 RapidOCR 识别每页图片，输出带置信度的文本行。若单页平均置信度低于配置阈值（默认 0.6），自动降级到 PaddleOCR V4 Lite 重新识别该页，并在后台日志中记录降级事件（含文件路径、页码、RapidOCR 平均置信度）。
2. **PaddleOCR**：固定使用 PaddleOCR V4 Lite，完全不加载或调用 RapidOCR。

**异步设计**：
- 多页面/多图片并行 OCR，通过线程池控制并发数
- 每个 OCR 任务返回：(text, bbox, confidence) 三元组
- 支持 OCR 结果缓存（同一文件重复扫描时跳过）

### 2.5 UIE 信息抽取模块

**职责**：基于 UIE（Universal Information Extraction）模型，从文本中抽取个人敏感信息。

**支持的抽取字段**：

| 字段 | Schema 名称 | 说明 |
|------|-----------|------|
| 姓名 | `name` | 中文人名 |
| 身份证号 | `id_card` | 18位身份证号码 |
| 手机号 | `phone` | 国内11位手机号 |
| 银行卡号 | `bank_card` | 16-19位银行卡号 |
| 地址 | `address` | 省市县街道详细地址 |
| 邮箱 | `email` | 电子邮箱地址 |
| 微信号 | `wechat` | 微信ID |
| 出生日期 | `birthday` | 出生年月日 |
| 工号 | `job_no` | 员工编号 |
| 车牌号 | `plate_no` | 车牌号码 |
| 护照号 | `passport` | 护照号码 |
| 性别 | `gender` | 性别信息 |

**模型选择**：

| 模型 | 精度 | 速度 | 推荐场景 |
|------|------|------|----------|
| UIE-Tiny | 较低 | 极快 | 高性能需求的轻量扫描 |
| UIE-Small | 适中 | 快 | 默认选择，平衡精度和速度 |
| UIE-Base | 最高 | 较慢 | 精度优先的合规审计场景 |

**抽取流程**：
1. 文本分片（默认每片 512 字符，含重叠 64 字符）
2. 对每片调用 UIE 推理
3. 收集所有实体的 (text, type, confidence, location) 四元组
4. 按置信度阈值过滤（默认 0.65）
5. 合并跨片的重复实体

### 2.7 规则校验与脱敏模块

**职责**：对抽取的实体进行格式校验、合规性检查、敏感信息脱敏。

**格式校验规则**：

| 字段 | 校验规则 |
|------|----------|
| 身份证 | 18位，校验位验证，出生日期合法 |
| 手机号 | 1开头的11位数字，号段合规 |
| 银行卡号 | Luhn 算法校验 |
| 邮箱 | 标准邮箱格式正则 |
| 出生日期 | 合法日期，不晚于今天 |

**脱敏策略**：

| 字段 | 脱敏方式 | 示例 |
|------|----------|------|
| 姓名 | 保留首字，其余掩码 | 张三 → 张* |
| 身份证 | 保留前6位后4位 | 110101199001011234 → 110101****1234 |
| 手机号 | 保留前3位后4位 | 13812345678 → 138****5678 |
| 地址 | 保留省市，街道门牌掩码 | 江苏省苏州市吴江区XX路X号 → 江苏省苏州市... |
| 银行卡号 | 保留前4位后4位 | 6222021234567890 → 6222****7890 |
| 邮箱 | 保留首字和域名 | zhangsan@163.com → z***@163.com |
| 微信号 | 保留前2位 | zhangsan123 → zh*** |

### 2.8 人员聚合统计模块

**职责**：跨文件合并同一数据主体，计算统计指标。

**跨文件合并策略**：
1. 主键优先：身份证号相同 → 直接合并
2. 次主键：身份证号缺失，姓名 + 手机号相同 → 合并
3. 弱关联：姓名相同 + 来源文件同目录 → 标记为疑似重复

**统计指标**：
- 数据主体总数
- 敏感字段总数（各类字段分别统计）
- 按风险等级的数据主体分布
- 数据主体平均信息完整度
- 发现频次 Top 10 的字段

### 2.9 LLM 识别模块（二期）

**职责**：对接企业内网大模型 API，对非文本文件（扫描件 PDF、图片）进行深度理解与字段抽取。

**适用场景**：

| 场景 | 一期方案限制 | 二期 LLM 增强 |
|------|-------------|---------------|
| PDF 扫描件（非文本） | OCR 依赖图片质量，表格结构丢失 | LLM 直接理解版面布局，还原结构化字段 |
| 图片中的复杂表格 | 合并单元格、跨行表格准确率低 | LLM 端到端还原表格结构 |
| 非中文文档 | UIE 仅支持中文 | LLM 多语言抽取 |
| 手写数字/文字 | UIE/PaddleOCR 准确率低 | LLM 多模态识别（若支持） |

**对接规范**：
- API 协议：OpenAI 兼容格式（`/v1/chat/completions`）
- 请求格式：System Prompt + 图片 Base64 / 文本内容
- 响应格式：JSON structured output
- 认证方式：API Key Header
- 超时设置：30s/请求（可配置）
- 重试策略：指数退避，最多 3 次

**交叉验证策略**：
```
OCR + UIE 结果 ──┐
                 ├──→ 置信度融合算法 → 最终字段
LLM 结果 ────────┘
```
- 两路结果取高置信度合并
- 冲突时以规则校验为准（如身份证校验码）
- LLM 提取但 UIE 未提取的字段，降权标记

**配置项**：
- `llm.enable` — 启用/禁用
- `llm.api_base` — API 地址
- `llm.api_key` — 密钥（加密存储）
- `llm.model` — 模型名称
- `llm.timeout` — 超时（秒）
- `llm.max_retries` — 最大重试次数
- `llm.confidence_boost` — 交叉验证时 LLM 权重

### 2.10 远程文件接入模块（二期）

**职责**：通过 FTP/SFTP/CIFS/SMB 协议远程连接文件服务器，发现并下载目标文件。

**架构设计**：

```
┌──────────────────────────────────────────────────┐
│                  文件源抽象层                       │
│  FileSource (接口)                                │
│  ├── connect() / disconnect()                    │
│  ├── list_dir(path) → FileInfo[]                 │
│  ├── download(remote_path, local_path)           │
│  └── test_connection() → bool                    │
├──────────────────────────────────────────────────┤
│  具体实现                                         │
│  ├── FTPFileSource     (ftplib)                  │
│  ├── SFTPFileSource    (paramiko)                │
│  ├── CIFSFileSource    (smbclient 或 pysmb)      │
│  └── SMBFileSource     (pysmb / smbprotocol)     │
└──────────────────────────────────────────────────┘
```

**处理流程**：

```
连接远程服务器 → 认证 → 目录浏览 → 文件列表获取
    → 按后缀过滤 → 流式下载到临时目录 → 送入文件解析管线
```

**凭据管理**：
- 支持用户名/密码、密钥文件（SFTP）、匿名访问（FTP）
- 凭据加密存储（`cryptography.fernet`）
- 前端提供连接测试按钮

**异常处理**：

| 场景 | 行为 |
|------|------|
| 连接超时 | 重试 2 次，失败则标记该源不可用 |
| 认证失败 | 记录错误，通知用户检查凭据 |
| 文件下载中断 | 断点续传（支持 FTP/SFTP），失败后跳过该文件 |
| 网络断开 | 自动重连，最多 3 次 |
| 文件过大 | 超过阈值（默认 500MB）跳过，记录到异常清单 |

## 3. 平台基础设施层

### 3.1 配置管理模块

**职责**：YAML 配置文件的读写、验证、前端联动。

配置项分组：

| 组 | 说明 |
|----|------|
| `scan` | 扫描路径、后缀过滤、子目录、压缩包 |
| `model` | 各模型路径、版本选择 |
| `inference` | 置信度阈值、分片大小、并发数 |
| `pdf` | PDF文本判定阈值 |
| `memory` | 内存上限、临时文件清理策略 |
| `log` | 日志级别、保留天数、文件大小 |
| `path` | 输出/临时/模型目录 |

### 3.2 模型自检与管理模块

**职责**：启动时校验模型文件完整性，运行时管理模型切换。

**自检内容**：
1. 检查模型目录是否存在
2. 检查必要模型文件是否存在
3. 验证文件大小是否在合理范围
4. 尝试加载模型，捕获加载异常

**自检输出**：

| 状态 | 含义 |
|------|------|
| ✅ 正常 | 模型可用 |
| ⚠️ 部分缺失 | 可选模型缺失，功能降级 |
| ❌ 缺失 | 必需模型缺失，无法工作 |

### 3.3 资源监控模块

**职责**：实时监控内存使用，防止 OOM。

**策略**：
- 每次加载模型前检查可用内存
- OCR/UIE 处理前检查内存水位
- 接近上限时等待正在进行的任务完成后再开始新任务
- 超过警戒线时自动触发 GC

### 3.4 日志与审计模块

**职责**：结构化日志记录、操作审计。

**日志分类**：

| 日志类型 | 说明 |
|----------|------|
| 系统日志 | 启动/停止/配置变更等系统事件 |
| 任务日志 | 每个文件的处理记录 |
| 审计日志 | 用户操作记录（开始扫描、导出报告、修改配置） |

**日志格式**：
```
[2025-01-15 10:30:45] [INFO] [文件处理] 处理完成: 张三简历.pdf | 抽取字段: 姓名,手机号,身份证 | 耗时: 3.2s
```

### 3.5 报告导出引擎

**职责**：将扫描结果输出为多种格式。

**导出格式**：

| 格式 | 内容 | 工具库 |
|------|------|--------|
| JSON | 完整结构化数据 | `json` |
| Excel | 多 Sheet 工作簿 | `openpyxl` |
| HTML | 可视化报告（内嵌图表） | `jinja2` |
| CSV | 失败文件清单 | `csv` |

## 5. 处理流程

### 5.1 端到端流程

```
用户点击 [开始扫描]
       │
       ▼
①  文件发现阶段
    ├── 遍历目录（可选递归）
    ├── 解压压缩包
    ├── 按后缀过滤
    └── 输出：文件清单列表
       │
       ▼
②  文档解析阶段
    ├── 按格式分派解析器
    ├── 提取纯文本内容
    └── 输出：每个文件的文本内容 + 结构化信息
       │
       ▼
③  PDF 判定阶段（仅 PDF 文件）
    ├── 检查是否有文本层
    ├── 有文本 → 文本提取
    └── 无文本 → 标记为 OCR
       │
       ▼
④  OCR 识别阶段
     ├── 读取配置中当前 OCR 引擎
     ├── 若为 RapidOCR（默认模式）：
     │   ├── 使用 RapidOCR 识别
     │   ├── 计算该页平均置信度
     │   ├── 若平均置信度 < 阈值（默认 0.6）→ 自动降级到 PaddleOCR 重新识别
     │   ├── 降级时记录日志：文件路径、页码、RapidOCR 平均置信度
     │   └── 输出：识别的文本行
     ├── 若为 PaddleOCR：
     │   └── 直接使用 PaddleOCR 识别，不调用 RapidOCR
     ├── 异步并行处理
     └── 输出：识别的文本行
       │
       ▼
⑤  UIE 信息抽取阶段
    ├── 文本分片
    ├── 每片调用 UIE 模型
    ├── 置信度过滤
    └── 输出：实体列表 (字段名, 值, 置信度, 位置)
       │
       ▼
⑥  规则校验与脱敏阶段
    ├── 格式校验
    ├── 合规校验
    ├── 脱敏处理
    └── 输出：校验后的实体列表
       │
       ▼
⑦  身份解析引擎(IPE)阶段
    ├── 标识分层
    ├── 文档内关联
    ├── 跨文件关联
    ├── 置信度计算
    ├── 完整度评分
    ├── 风险等级评定
    └── 输出：数据主体档案
       │
       ▼
⑧  报告生成阶段
    ├── 统计指标计算
    ├── 生成 JSON 结果
    ├── 生成 Excel 报表
    ├── 生成 HTML 报告
    ├── 生成 CSV 失败清单
    └── 输出：报告文件
       │
       ▼
用户查看/下载报告
```

### 5.2 并行化策略

```
时间线 →
文件1: [解析]→[OCR]→[UIE]→[脱敏]→[IPE]→★
文件2:   [解析]→[OCR]→[UIE]→[脱敏]→[IPE]→★
文件3:     [解析]→[OCR]→[UIE]→[脱敏]→[IPE]→★
文件4:       [解析]→[OCR]→[UIE]→[脱敏]→[IPE]→★
                ↑      ↑      ↑
          文件解析线程池  OCR线程池  UIE线程池
                        （各模块可独立配置并发数）
★ = 同步点（IPE需要等待所有文件完成）
```

### 5.3 二期流程扩展

二期新增 **大模型识别** 和 **远程文件源** 两个分支，与一期管线互不冲突：

**分支 A：文件源选择**
```
一期：扫描本地目录 ──→ 文件清单
二期：FTP/SFTP/CIFS/SMB ──→ 文件清单（流式下载到本地临时目录）
混合：本地目录 + 远程源 ──→ 合并文件清单
```

**分支 B：非文本文件识别**
```
一期：PDF判定 → OCR → UIE（纯离线私有模型）
二期：PDF判定 → LLM 图文识别 → 字段抽取
    （或交叉验证模式：OCR+UIE 与 LLM 并行走两路取高置信度）
```

**二期管线调度策略**：
- 远程文件扫描与本地扫描共用同一套格式解析、IPE、报告管线，仅文件发现阶段不同
- LLM 识别与 OCR+UIE 互为替补（LLM 不可用时降级至一期方案）
- 开启交叉验证时，并发走两路，以先返回 + 高置信度结果为准

### 7.4 状态与交互约定

| 场景 | 行为 |
|------|------|
| 首次启动/无数据 | 工作台统计卡片显示 0，扫描任务列表显示"暂无任务"空状态 |
| 任务运行中 | 扫描报告页面实时更新进度，导出按钮置灰 |
| 任务失败 | 扫描报告页面显示失败状态及原因，导出按钮可用（如有部分结果） |
| 模型缺失 | 系统设置页面对应模型状态显示"✗ 缺失"，扫描时提示并阻止启动 |
| 脱敏开启 | 所有展示的姓名、身份证、手机号等字段自动脱敏 |
| 配置实时生效 | 修改系统设置后立即写入文件，无需点击保存按钮 |
